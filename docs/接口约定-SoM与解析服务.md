## 0. 背景（一句话）

原工程靠「无障碍节点树 / 端侧 OCR → 文本 → 大模型回选项字母 → 本地在节点/框里找回可点目标」。
改造后新增两条能力：

1. **SoM 编号标注（Set-of-Mark，纯端侧）**：APK 把候选点击元素画成**带编号的框**贴进截图，并把「编号 → 元素文本」清单一起发给多模态模型，让模型直接**回编号**；点击时优先用该编号对应的框中心，绕开「WebView 选项 `clickable=false` 点不中」与「OCR 认不出图标」。
2. **OmniParser 本地解析服务（PC 侧 Python）**：APK 把截图 POST 给 PC 上的解析服务，拿回结构化元素（YOLO 图标检测 + Florence-2 图标语义 + 文字框）；它既是**识别源③**（节点树与 OCR 都读不到题时兜底），也是 SoM 的元素来源之一。

## 1. 解析服务 HTTP 契约（Python 侧实现，Android 侧消费）

默认监听 `0.0.0.0:8010`。**只有两个端点**，不要新增。

### 1.1 `GET /health`

成功 200，`Content-Type: application/json; charset=utf-8`：

```json
{
  "ok": true,
  "service": "omniparser-service",
  "version": "1.0",
  "mode": "real",
  "backend": "lite",
  "device": "cpu",
  "caption_enabled": true,
  "weights": {"som_model": "weights/icon_detect_v3/model.pt", "caption_model": "weights/icon_caption_florence"},
  "uptime_s": 12.3
}
```

- `mode`：`real` | `mock`（`--mock` 时不需要权重，返回**明确标记的假元素**，仅用于链路自测）。
- `backend`：`lite`（默认，只用 YOLOv9 + Florence-2 + easyocr）| `upstream`（原样调用 `util/omniparser.py` 全量管线）。
- 模型没就绪时返回 503 + `{"ok": false, "error": "<原因>"}`；**服务在 real 模式下缺权重必须直接退出**（退出码 2），不要"起来但装死"。

### 1.2 `POST /parse`

请求体（JSON，UTF-8）：

```json
{
  "image_base64": "<JPEG 或 PNG 的 base64，不带 data: 前缀>",
  "box_threshold": 0.05,
  "annotate": false,
  "max_elements": 200
}
```

- `box_threshold`：可选，缺省用服务端启动参数（默认 `0.05`）。
- `annotate`：可选，**缺省 `false`**。为 `true` 时额外返回 `som_image_base64`（**服务自己**编号的标注图，编号与 `elements[].id` 一致）。
- `max_elements`：可选，缺省 `200`，超出直接截断（保序）。

成功 200：

```json
{
  "ok": true,
  "mode": "real",
  "image": {"width": 720, "height": 1600},
  "elapsed_ms": 1234,
  "elements": [
    {
      "id": 1,
      "type": "text",
      "label": "关闭",
      "text": "关闭",
      "bbox_ratio": [0.612, 0.121, 0.702, 0.146],
      "bbox_px": [441, 194, 505, 234],
      "interactable": true,
      "source": "ocr"
    },
    {
      "id": 2,
      "type": "icon",
      "label": "magnifying glass",
      "text": "",
      "bbox_ratio": [0.03, 0.02, 0.09, 0.06],
      "bbox_px": [22, 32, 65, 96],
      "interactable": true,
      "source": "icon"
    }
  ],
  "som_image_base64": "<仅 annotate=true 时存在>"
}
```

字段逐条约定：

| 字段 | 类型 | 约定 |
|---|---|---|
| `ok` | bool | 成功恒为 `true` |
| `image.width/height` | int | **提交图片**的像素尺寸（不是缩放后、不是归一化） |
| `elapsed_ms` | int | 服务端本次推理耗时 |
| `elements[].id` | int | **1 起、唯一、按序**：先全部文字元素（按 `bbox` 从上到下、从左到右），再全部图标元素（同样排序）。该顺序同时决定 `annotate=true` 时图上的编号 |
| `elements[].type` | string | `"text"` \| `"icon"` |
| `elements[].label` | string | 给模型/人看的短标签；text 元素就是文本本身，icon 元素是 Florence-2 的语义描述（`--no-caption` 时为 `"icon"`） |
| `elements[].text` | string | text 元素的原文；icon 元素为 `""` |
| `elements[].bbox_ratio` | float[4] | `[x1,y1,x2,y2]`，**0..1 归一化**，相对提交图片，`x1<x2, y1<y2`，越界要裁剪到 `[0,1]` |
| `elements[].bbox_px` | int[4] | 同一框的像素整数版，`round(ratio*size)`，便于下载图片直接画框核对 |
| `elements[].interactable` | bool | 是否疑似可交互（YOLO 检测到的图标恒 `true`；文字元素按启发式给，拿不准给 `true`） |
| `elements[].source` | string | `"ocr"`（文字）\| `"icon"`（图标检测） |
| `som_image_base64` | string | 可选；JPEG base64，尺寸与提交图片**一致**，编号与 `elements[].id` 一致 |

错误应答（HTTP 状态码非 2xx，体统一为 `{"ok": false, "error": "<人话>"}`）：

| 码 | 触发条件 |
|---|---|
| 400 | 请求体不是合法 JSON / `image_base64` 缺失或不是合法 base64 图片 |
| 413 | 提交图片超过服务端上限（默认 12 MB） |
| 500 | 推理期异常（体里带 `error`） |
| 503 | 模型未就绪 |

**幂等性**：`/parse` 无副作用、可并发；服务端要自己串行化模型推理（同一时刻只跑一次推理），避免显存/CPU 互相挤。

## 2. SoM 编号与提示词契约（Android 侧内部）

> **重要：服务端编号 ≠ 发给模型的编号。** APK 把三路来源（无障碍节点、端侧 OCR、解析服务）合并后**重新编号**为 `E1..EN`，模型只看 APK 给的编号。这样两侧可以各自独立演进。

### 2.1 元素合并与编号（APK 侧）

来源优先级（同一个框只保留一个，先到先得；判定用 `IoU > 0.6` 或包含关系）：

1. `source="node"`：无障碍节点树里的有界文本节点（文本最准，坐标最准）；
2. `source="ocr"`：端侧 OCR 行（坐标要按 `OcrResult.scaleX/scaleY` 换算回屏幕坐标）；
3. `source="omniparser"`：解析服务返回的元素（图标语义是它的独有价值）。

丢弃规则：任一边 `< 8px`、面积 `> 屏幕面积 60%`、或与已保留元素重叠超阈值。保留上限取 `prefs.somMaxElements`（默认 `40`），保序截断。

**重叠（重复）判定的 v1.1 细化**：两个框算「同一个」只有两种情形 ——
- `IoU > 0.6`（大小相近的同一处，例如节点行与同一行的 OCR 行）；或
- 存在包含关系**且两框面积相差不到 4 倍**。

**容器比子元素大 4 倍以上时不算重复，两者都保留** —— 否则一个覆盖整屏/整卡的容器文本节点会把里面的 A/B/C/D 选项框全部吞掉，SoM 清单里就只剩容器那一行，编号点击这条路等于废掉（真实反例见 `verify/验证报告.md`）。

最终编号顺序：按框**从上到下、同一行从左到右**（`centerY` 分桶 30px 内视为同一行），重新编 `E1..EN`。

### 2.2 发给模型的清单（user 消息里，紧跟屏幕文字之后）

```
【界面元素（对应图中编号的框）】
E1 文本 关闭
E2 文本 A. 对
E3 图标 magnifying glass
```

### 2.3 模型回复协议（向后兼容，新增可选字段）

- 纯文本（预设提示词通道）：`B` 或 `B E7`（选项字母在前，可选元素编号在后）。
- JSON（用户自定义为 JSON 时）：新增可选字段 `"element_id": 7`。

解析规则（`LlmClient.parseAnswer`）：

- `element_id` / `E<数字>` / `元素<数字>` / `#<数字>` 都能认，取第一个命中；解析不出就是 `null`，**绝不猜**。
- 老格式（只有字母、只有 JSON 不含 `element_id`）行为与 v1.3 完全一致。

### 2.4 点击优先级（`ScreenOcrAccessibilityService`）

1. 模型给了 `elementId` 且能在本次 SoM 列表里找到该元素 → **用它**（这就是"点得准"的来源）。
   - 反矛盾保护（v1.1 写实判据）：把该元素的标签抽成「归属标记」——**必须是标签开头的显式选项标记**（`A`–`H` 字母 / `①`–`⑧` 圈号 / `1`–`8` 数字，且后面跟分隔符或整串就是该标记）。**长标签同样参与判定**，不得因为标签>12 字就放弃归属（这正是 v1.0 的漏判来源）。抽不出标记（中文单字 `对`/`错`、图标描述 `magnifying glass`、自由文本）→ 不算矛盾。模型答案与元素标记**只在同一标记族内比较**（字母对字母、数字对数字）；两族不同 → 不算矛盾，照用编号。判为矛盾时**不用**它，退回第 2 条并打警告日志。
2. 退回现有 `ClickPlanner`（节点文本匹配 → 可点祖先 → OCR 框中心）。
3. 两条都拿不到 → 不点（保持原「宁可不点，不要点错」的纪律）。

点击动作本身复用现有 `clickAtPoint(x, y, label)`（最深叶子 `ACTION_CLICK` → 可点节点 → 可选 root tap → 坐标手势），**不要新写一套点击**。

## 3. 降级与失败纪律

- 解析服务**任何失败（连不上 / 超时 / 非 2xx / JSON 不合契约）都不得中断主流程**：记日志、返回 `null`，后续按"没有它"继续。
- `somEnabled=false` 时：不发标注图、不发元素清单、不解析编号，行为回到 v1.3。
- 解析服务默认**关闭**（`omniParserEnabled=false`），因为 PC 侧服务不一定在跑。
- 手机连 PC 的两种方式（写进文档）：同一局域网用 PC 的 IP；或 `adb reverse tcp:8010 tcp:8010` 后用 `http://127.0.0.1:8010`。

## 4. 服务端实现要点（Python 侧，避免重复踩坑）

- 上游 `util/utils.py` **模块导入即**执行 `easyocr.Reader(['en'])` 与 `PaddleOCR(...)`，还依赖 `openai/matplotlib/supervision`。因此默认 `lite` 后端**不要 import `util.utils`**，只复用：
  - `util/yolov9.py` 的 `YOLOv9Detector`（TorchScript，`predict(source, conf=..., imgsz=640, iou=0.7, max_det=300)`，返回 `[Result(boxes.xyxy, boxes.conf)]`，坐标已是**像素**、相对输入图）；
  - Florence-2 的调用方式（抄 `util/utils.py::get_caption_model_processor` 与 `get_parsed_content_icon` 的 crop→64×64→`<CAPTION>` 批量推理那段，注明出处）。
- `--backend upstream`：原样 `from util.omniparser import Omniparser`，需要上游全量依赖（paddleocr 等），仅作对照保留。
- 权重目录 `omniparser-service/weights/`：`icon_detect_v3/model.pt`、`icon_caption_florence/{config.json,generation_config.json,model.safetensors}`，靠 `download_weights.ps1` 从 HuggingFace 取（国内用 `HF_ENDPOINT=https://hf-mirror.com`，已实测可达）。
- 只用标准库 `http.server` 起服务（不引 FastAPI），依赖越少越好；`POST /parse` 的推理串行化用一把 `threading.Lock`。

## 6. 答完自动推进（v1.2 新增，唯一口径来源）

需求原话：「加入滚动功能，当当前页面题目已全部完成后，自动翻页或者点击下一题」。

### 6.1 什么时候允许推进（判定口径）

「当前页题目已全部完成」= 当前屏**没有仍需作答的可见题目**。两条路径都要覆盖：

1. 本地判定 `!q.isCandidate`（整屏不像题目）；
2. 判为题目但属于**刚答过的重复**（既有去重分支），且 `submitState()` 为 `DONE` 或（补提交后仍）`UNKNOWN` —— 也就是既有流程决定「只补收尾、不重复作答」的那一刻。

**仍为 `PENDING`（浮层里还亮着「提交作答」）时绝不推进** —— 那说明还有没答完的题。

### 6.2 可见性（v1.2 新增，安全底线）

「可见」= 框与 `Rect(0, 0, 截图宽, 截图高)` **相交且面积 > 0**（严格相交：贴边零重叠算不可见）。

- **推进按钮**只接受可见节点。长页面里折叠线以下的按钮虽然**仍在无障碍节点树里**，但 bounds 在屏幕外，点它的中心会点到别处；
- **点击 / 元素编号目标**若不可见 → **不点**，打日志并转为「滚动把它带进来」。这条同时修掉长页面里点到屏幕外的既有隐患。

### 6.3 动作优先级

**先点可见的推进按钮 → 没有可见按钮才滚动。**

- 按钮点击复用既有 `clickAtPoint`（最深叶子 `ACTION_CLICK` → 可点节点 → 坐标手势），不新写点击；
- 滚动：先试**可滚动节点的 `ACTION_SCROLL_FORWARD`**（取覆盖题目区域、`isScrollable` 的最深节点）；失败再用 `dispatchGesture` 上滑：从 `(w/2, h*0.85)` 到 `(w/2, h*0.15)`（位移 0.70 屏高），持续约 300ms，落点复用既有 ±10px 抖动。
  - **v1.2.2 修正**：v1.2/v1.2.1 写的 `0.78h → 0.28h`（位移 0.5 屏高）**已作废** —— 真机实测 0.5 屏高的位移在长页面上推进太慢，实现已改为 **0.85h → 0.15h**，本节以代码为准。
  - 节点滚动**返回 true 但画面没动**时不得直接判「到页尾」：先置 `nodeScrollIneffective`，下一次推进**直接走手势**（契约 §6.5 无进展检测）。

### 6.4 推进按钮词表与匹配规则

关键词（**按长度从长到短匹配**）：`继续下一题`、`下一部分`、`下一题`、`下一页`、`下页`、`下一节`、`下一讲`、`下一章`、`下一关`、`下一步`、`下一个`。
**不含裸「继续」**（它已在收尾关闭词表里，语义冲突）。

匹配规则（**前缀 + 去括号装饰 + 后缀「不得含字母」**，v1.2.3 定稿）：

1. 取节点 `text`（空/全空白则取 `contentDescription`），`trim` 后必须**以某个关键词开头**（多关键词命中时取最长者）；
2. **先把成对括号包裹的整段内容删掉**：`（…）`、`(…)`、`【…】`、`[…]`、`《…》`、`〈…〉`、`«…»`（括号内任意内容，成对即可）；
3. **剩下的部分只要不含「字母类字符」（Unicode 类别 L*，含 CJK 表意文字）就算合法**；等价实现：`rest.none { Character.isLetter(it) }`。

> **为什么从「白名单」改成「否定式」（v1.2.3，真机逼出来的）**：真实 App 的按钮文本常带**图标字体私有区字符**。实测智慧树考试页的「下一题」节点文本是
> `下一题` + **U+E641**（PUA，图标字体的箭头），白名单式判据必然漏掉它 → App 找不到明明可见的按钮 → 退化成滚动 → 在不滚动页面上卡死。
> 白名单永远追不上各家图标字体（U+E000–U+F8FF、U+F0000–U+FFFFD），而「后缀含中文/字母才算另一个词」才是真正的意图（`下一题练习`/`下一步骤` 都是靠这条被排除的）。

判定示例：
- **命中**：`下一题`、`下一题。`、`下一题 >`、`下一题 »`、`下一题(1/10)`、`下一题 3/10`、` 下一题 `、`下一题《2》`、`下一题 ３/10`（全角）、`继续下一题`、`下一关【第2关】`、`下一题—`、`下一步：`、**`下一题\ue641`（智慧树实测）**、`下一题\ue641 `、`下一题\u200b`（零宽空格）；
- **不命中**：`下一题练习`、`下一题目`、`下一题目的说明`、`下一步骤`、`下一题答案`、`下一题 Next`、`下一题Ａ`（全角字母）、`下一题a`、`点击下一题`（前缀不符）、`上一题`、`下一題`（繁体也算字母）、`继续`、`继续观看`、`Next`（首字母非关键词）、空串。

图标按钮靠 `contentDescription`（NodeReader 已支持 text‖contentDescription）覆盖。

### 6.5 护栏（缺一不可）

| 护栏 | 取值 | 说明 |
|---|---|---|
| 只在本会话答过题后生效 | 计数 ≥1 | 成功点击选项后 +1；**前台包名变化**时清零；为 0 不推进（防止在无关应用里乱滚） |
| **推进窗口（v1.2.2）** | `ADVANCE_WINDOW_MS = 60_000`，以**最近一次成功作答时刻**为基准 | 超出窗口即停止推进，直到下一次作答再激活。**成功推进不刷新窗口**。目的：答完题后最多推进 60s（每分钟约 15 次滚动，足够走到下一页/下一题），避免在视频/长文档页面**无限滚动**打扰用户 |
| 推进冷却 | `ADVANCE_COOLDOWN_MS = 4000` | 两次推进的最小间隔 |
| 无进展检测 | `ADVANCE_BLOCK_MS = 60_000` | 滚动前记下 `OcrResult.signature`，下一次分析签名未变 → 节点滚动则记 `nodeScrollIneffective` 改手势；手势也没变 → 判「已到页尾」，暂停推进 60s |
| 连击上限 | `prefs.autoAdvanceMaxStreak`（默认 3，1~10） | 连续推进 N 次仍未见新题 → 暂停 60s 并清零；新题出现时也清零。**无效的节点滚动不计入连击**（v1.2.2：节点滚动的计数推迟到下一轮确认「签名确实变了」才结算） |
| 试运行 | `prefs.dryRun` | 只打日志、不动作 |
| 屏幕处理开关 | `prefs.processingEnabled=false` | 完全不做 |
| 与既有冷却并存 | — | 不得绕过 `clickCooldownMs`/`CLOSE_COOLDOWN_MS`，也不得被它们吞掉 |

> **v1.2.2 补充（真机逼出来的两条）**：
> 1. **非题目屏幕也必须能触发推进**。v1.2/v1.2.1 的实现把「屏幕不是题目」在 `onOcr` 里提前 `return` 掉了（`!q.isCandidate && !omniAvailable`），于是「题目全做完 → 页面没题了 → 翻页」这条**主路径在解析服务默认关闭时永远不可达**。真机实测：长页面滚到空白区后推进彻底停止。修法：该分支必须**先调度推进再返回**，不得直接吞掉。
> 2. **推进窗口**（上表）：避免「答过题之后在视频/长文档页无限滚动」。

### 6.6 日志（逐字，用于真机验收）

`⑨ 推进：已点「下一题」（坐标 x,y）` ｜ `⑨ 推进：当前屏没有可见的推进按钮，改为向下滚动` ｜ `⑨ 推进：可滚动节点 ACTION_SCROLL_FORWARD 成功` ｜ `⑨ 推进：改用上滑手势（x1,y1 → x2,y2）` ｜ `⑨ 推进：滚动后画面未变化（已到页尾？），暂停推进 60s` ｜ `⑨ 推进：连续 N 次推进后仍未见新题，暂停推进 60s` ｜ `⑨ 推进：当前屏仍有未作答题目，不推进` ｜ `⑨ 推进：本应用本次会话还没答过题，不推进` ｜ `⑨ 推进：冷却中（距上次 1.2s < 4.0s）` ｜ `⑨ 推进：目标在屏幕外，先滚动把它带进来` ｜ 试运行：`⑨ 试运行：本应推进（…），已跳过`

**v1.2.2 新增的 5 条（真机验收也会 grep）**：
- `⑨ 推进：节点滚动无位移，改用上滑手势重试`
- `⑨ 推进：节点滚动此前无位移，直接改用上滑手势`
- `⑨ 推进：距上次作答已 Ns（> 60s 窗口），不推进`
- `⑨ 推进：本轮无需作答（<原因>）→ 2400ms 后检查是否推进`
- `④ 判定为非题目（解析服务未开启/不可用）→ 交给推进判断`（D-d 修复点，非 `⑨` 前缀）

### 6.7 开关与默认值

- `autoAdvanceEnabled`（键 `auto_advance_enabled`）：**默认 `true`**，界面可关；
- `autoAdvanceMaxStreak`（键 `auto_advance_max_streak`）：**默认 3**，界面可填 1~10；
- 已知边界：推进只在「答过题之后」生效，**不能当通用滚动器**用。

## 7. 答题完毕收尾：直接提交 / 继续答题（v1.3 新增；**v1.4 判定口径改版**）

需求原话：「加个可以自主设置答题完毕后是直接提交还是继续答题（等同于直接退出）」。
人类确认的口径：**提交 = 自动点顶部「提交作业」并在确认弹窗里点确认；继续答题 = App 停手（不提交、不再点任何东西，等同于退出）**；「答题完毕」**必须**经过题卡校验。

> ### ⚠️ v1.4 变更（相对 v1.3，**以本节为准**）
> 1. **判定「整卷答完」改用题号**，不再用 `answeredCount >= N`（App 自己点过几题）：
>    识别到卷面标题 → 点开题卡取**最大题号**当总题数 N → **当前题号 < N 就继续作答**；`当前题号 == N` 才进入收尾。
>    为什么改：人类手动答过的卷子上 App 一次都没点过，`answeredCount` 恒为 0，**永远判"未答完"、永远不提交**。
> 2. **提交前增加一道确认**：最后一题必须**确实处理过**（在去重记录里）。因为题号只说明"翻到了"最后一题，
>    不说明"答了"它；平台读不到每题作答标记（见 7.1 的说明），少了这道闸就会**交白卷**。
> 3. **收尾不再关闭题卡面板**：实测该面板用坐标点 4 次都关不掉，反而把整条收尾卡死。
>    现在读完题号**直接进入判定/提交** —— 提交本身会让平台关闭面板。
> 4. **新增「卷尾提示」触发**：平台在最后一题点「下一题」时会显示 `这已经是最后一道题了`（页面里的 TextView，
>    节点树直接读到；只显示约 1 秒）。按**关键字**匹配，命中即允许立刻做整卷校验。
> 5. **弹窗提示文案**：实测提交确认弹窗可能写着「**你已全部完成本次作业，确认要交卷吗？**」，确认按钮是 `确认`。
> 6. **停手状态新增自动解除**：同一 App 内手动换卷时包名不变，原口径会让停手永不解除；现在**卷面标题变化即自动解除**。
> 7. **判据细节**：去重键在「选项正文过短」时**必须带上题干**——实测判断题选项恒为 `对/错`，
>    键恒为 `A:错|B:对`（7 字符），同卷所有判断题共用一个键 → 答过一题后其余全被判"已答"。
> 8. **选项配对的硬要求**（`NodeReader.merge`）：正文必须落在标签**右侧**并按水平距离取最近。
>    实测 `A Python / B Java / C C++ / D C` 这类题，若只判"同一行"就会让标签 `C` 抢走正文列的 `C++`、
>    并把选项 `D`（正文是字母 `C`）整条丢掉 → App 点错行且平台侧该题从未作答。

### 7.1 判定「整卷答完」——**题号口径**（v1.4）

> **为什么不用题卡的「已答/未答」标记**：实测智慧树题卡的题号节点是
> `resource-id=tv_question_position class=TextView text="1" selected=false checked=false content-desc=""`
> —— 「已答/未答」**只体现在背景颜色上，无障碍节点里读不到**（v1.4 又复测一次：连 `selected`/`checked` 全为 false）。
> 所以既不能读"已答"标记，也不能靠 App 自己记账（手动答过的卷上会恒为 0），只能**用题号**。

流程：

1. **取总题数 N**：识别到**卷面标题**（形如 `第八章单元测试`，判据：长度 4~30 且同时含「第」与（章/单元/节/讲/关/部分））后，
   点开题卡，统计「纯数字文本」题号节点（`text` 匹配 `^\d{1,3}$`），**N = 这些数字的最大值**；
   N = 0 或 > 200 视为不可信，放弃判定（打日志、不做动作）。
   日志：`⑩ 收尾：题号明细（N 个纯数字节点）：1,2,3,…`、`⑩ 进度：本卷总题数 N=…（取题卡最大题号），当前第 k 题 → …`。
2. **取当前题号 k**：从 `^\d{1,3}\s*[.、．]\s*\S{0,6}题` 这类题号行解析（如 `8. 单选题（2分）` → 8）；
   读不到返回 0，此时**保守地按"还有题要答"处理**。
   日志（题号变化时打）：`PAGE# 当前题号=k（读到「…」）`。
3. **推进判据**：`k < N` → 继续作答并推进（并**清掉**"按钮无反应/滚动无位移"造成的推进暂停，否则会卡住）；
   `k == N` → 进入收尾判定。
4. **收尾前的确认**：最后一题必须**确实处理过** —— `answeredForFinish >= N`，**或**最后一题的去重键
   命中 `isRecentlyAnswered`（该题在去重窗口内被处理过）。两者都不成立 → 日志
   `⑩ 收尾：题号 k/N（最后一题已处理=false…）→ 尚未答完`，继续推进，**不提交**。
5. 成立 → 日志 `⑩ 收尾：已到最后题且已处理（题号 N/N）→ 执行收尾`，进入 §7.2。

**卷尾提示（v1.4 新增触发源）**：节点树里出现 `这已经是最后一道题了` 或其变体
（`END_PAPER_KEYWORDS`：`这已经是最后一道题了`/`这已经是最后一道题`/`已是最后一道题`/`已经是最后一题`/`这已是最后一题`/`已是最后一题`；
兜底：长度 ≤20 的短文本同时含「最后」与「题」）时，视为平台给的"到卷尾"信号，**该轮即可发起整卷校验**
（强制校验**不受 20s 限频约束**）。命中日志：`⑩ 收尾：识别到卷尾提示「…」…`。
**注意**：提示只说明"到卷尾"，不等于"这题答了" —— 所以第 4 步的确认仍然必须过。

**换卷（v1.4）**：卷面标题与"停手时那份卷"不同 → 自动解除停手，并按新卷重新取 N。

**日志（逐字）**：`⑩ 收尾：点开题卡统计题目（共 N 题）`、`⑩ 收尾：没找到「题卡」入口，放弃判定`、
`PAGE# 当前题号=k（读到「…」）`、`⑩ 收尾：已到最后题且已处理（题号 N/N）→ 执行收尾`。
> 历史口径（v1.3，已废弃）为 `⑩ 收尾：已答 M/N，尚未答完`（`answeredCount >= N`）。

### 7.2 收尾动作

开关 `finishMode`：`off`（默认）｜ `submit`（直接提交）｜ `idle`（继续答题=停手）。

- **`off`**：什么都不做（保持原有行为）。
- **`submit`**：
  1. 找**可见**的提交按钮：`text` 或 `contentDescription` 精确等于 `提交作业`/`提交考卷`/`交卷`/`提交答案`/`确认提交`（沿用 NodeReader 的 text‖desc 口径）；
  2. 找不到 → 日志 `⑩ 收尾：没找到「提交作业」按钮，放弃自动提交`，**不猜、不点**；
  3. 找到 → 点它 → 等 ~1.2s → **读弹窗**：
     - 弹窗文本里出现 `未作答`/`还有`/`未完成`/`不能提交` → 日志 `⑩ 收尾：提交前弹窗提示未作答，已取消提交`，并尝试点 `取消`/`关闭`（找不到就只是停手）；
     - 否则找确认按钮：`text` 精确等于 `确认`/`确定`/`确认提交`/`提交`/`好的`/`是` → 点它 → 日志 `⑩ 收尾：已点「确认提交」（坐标 x,y）`；
     - **读不到任何确认按钮就不点**（日志 `⑩ 收尾：弹窗里没读到确认按钮，已放弃提交`）——宁可不交，不可乱点。
     - **v1.4 实测弹窗文案**：`你已全部完成本次作业，确认要交卷吗？` + 按钮 `确认` / `取消`（属上面认可的确认词表）。
  4. 提交后进入停手状态（见 §7.3）。
- **`idle`**：日志 `⑩ 收尾：已答完（题号 N/N）→ 按设置「继续答题」停手（不再操作本应用）`，进入停手状态。

### 7.3 停手状态（两个模式共用）

判定答完并执行完动作后，置「已停手」：

- **不再做任何自动化动作**（不判题、不调用接口、不点击、不推进）——语义上等同退出；
- 无障碍服务与轮询**保持存活**，但每轮只写一行日志：`⑩ 已停手：本应用已答完，等待前台切换`；
- **解除停手的两个条件**（v1.4 新增第二个）：
  1. **前台包名变化**（切到别的 App 再回来视为新一轮）；
  2. **卷面标题变化** —— 同一 App 内手动换卷时包名不变，原口径会让停手永不解除。
     实现：停手期间每轮读可见文本里的卷面标题，与"停手时那份卷的标题"不同即解除，并清零
     `answeredForFinish`/`answeredThisSession`/`stuckAtEndMs`/推进暂停等，按新卷重新取 N。
     日志：`⑩ 收尾：检测到换卷（旧标题 → 新标题）→ 解除停手，按新卷继续答题`。

### 7.4 试运行与安全

- `prefs.dryRun=true` 时：**只打日志不动作** —— `⑩ 试运行：本应提交（…），已跳过` / `⑩ 试运行：本应停手（…），已跳过`（人类要求：首次先干跑观察判据）；
- 题卡检查**限频**：两次检查之间至少 20s，且同一次分析里只做一次（避免反复开关面板）；
- 任何一步失败都**不得**导致误提交：读不到按钮/弹窗一律放弃并打日志。
